## 자원(Resource): 커널의 관리 하에 프로세스에게 할당/반납되는 수동적 개체(passive entity)

---

## 자원의 분류
- 하드웨어 자원
  - 프로세서, 메모리, 디스크, 모니터, 키보드 등
- 소프트웨어 자원
  - 메세지, 신호, 파일, 설치된 소프트웨어

 ---
 
## Process Control Block(PCB)
- OS가 프로세스 관리에 필요한 정보 저장
- 프로세스 생성 시 생성됨

<img width="810" height="500" alt="image" src="https://github.com/user-attachments/assets/ed316950-de5c-4eb5-8864-1bbf9ff32116" />

### PCB가 관리하는 정보
- PID
  - 프로세스 고유 식별 번호
- 스케줄링 정보(스케줄링: CPU를 어떤 프로세스에게 언제, 얼마나 할당할 것인가를 결정하는 것
  - 프로세스 우선순위 등과 같은 스케줄링 관련 정보들
- 프로세스 상태
  - 자원 할당, 요청 정보 등
- 메모리 관리 정보
  - Page table, segment table 등
- 입출력 상태 정보
  - 할당받은 입출력 장치, 파일 등에 대한 정보 등
- 문맥 저장 영역
  - 프로세스의 레지스터 상태를 저장하는 공간 등
- 계정 정보
  - 자원 사용 시간 등을 관리

** PCB 정보는 OS별로 서로 다르며, PCB 참조 및 갱신 속도는 OS의 성능을 결정짓는 중요한 요소 중 하나이다. **

## 프로세스의 상태(Process States)
- 프로세스 - 자원 간의 상호작용에 의해 결정
- 프로세스 상태 및 특성
  <img width="942" height="304" alt="image" src="https://github.com/user-attachments/assets/3e224f28-b11c-4f2b-b86b-7f813f732ac0" />

  1. 생성된 상태 (Created State)
  - 작업(Job 또는 Program)을 커널에 등록
  - PCB 할당 및 프로세스 생성
  - 커널
    - 가용 메모리 공간 체크 및 프로세스 상태 전이(메모리 할당 시 Ready 또는 대기중일 때 Suspended ready)

  2. Ready State
  - 프로세서 외 다른 모든 자원을 할당받은 상태
    - 프로세서 할당 대기 상태
    - 즉시 실행 가능 상태
  - Dispatch (or Shedule)
    - Ready state -> Running state
   
  3. Running State
  - 프로세서와 필요한 모든 자원을 할당받은 상태
  - Preemption
    - Running state -> Ready state
    - 프로세서 스케줄링
  - Block / Sleep
    - Running state -> Asleep state
    - I/O등 자원 할당 요청
   
  4. Blocked / Asleep State
  - 프로세서 외 다른 자원을 기다리는 상태
    - 자원 할당은 System call에 의해 이루어짐
  - Wake-up
    - Asleep state -> Ready state

  5. Suspended State
  - 메모리를 할당 받지 못한(빼앗긴) 상태
    - 메모리 이미지를 swap device(프로그램 정보 저장을 위한 특별한 파일 시스템)에 보관
    - 커널 또는 사용자에 의해 발생

  6. Terminated/Zombie State
  - 프로세스 수행이 끝난 상태
  - 모든 자원 반납 후, 커널 내에 일부 PCB 정보만 남아있는 상태
    - 이후 프로세스 관리를 위해 정보 수집
