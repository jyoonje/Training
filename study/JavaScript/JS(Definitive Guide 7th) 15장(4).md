동일 출처 정책

동일 출처 정책(same-origin policy)은 **자바스크립트 코드에서 접근할 수 있는 웹 콘텐츠를 제어**하는 보안 제한이다.
구체적으로 말해 스ㅡ크립트는 자신을 포함한 문서와 같은 서버에서 가져온 창과 문서의 프로퍼티만 읽을 수 있다.

호스트가 같더라도 다른 포트에서 가져온 문서는 출처가 다른 것으로 간주한다. 또한 http: 프로토콜과 https: 프로토콜로 가져온 문서 또한 출처가 다르다고 간주한다.

스크립트 자체의 출처는 동일 출처  정책과 관련이 없다. 문제가 되는 것은 스크립트를 포함한 문서의 출처이다.

자바스크립트 코드는 자신을 포함하는 문서를 가져온 웹 서버에 HTTP 요청을 제한 없이 보낼 수 있지만, 다른 웹 서버와 통신할 수는 없다.(CORS로 허용된 웹 서버는 허용됨)

동일 출처 정책을 완화하는 두 번째 방법은 CORS(Cross-Origin-Resource-Sharing)(교차 출처 간 자원 공유)이다.
CCORS는 HTTP를  `Origin:`요청 헤더와 Access-Control-Allow-Origin 응답 헤더로 확장한다.


### 15.2 이벤트
이벤트 방식의 프로그래밍은 웹 프로그래밍에만 그치지 않으며, 그래픽 사용자 인터페이스를 사용하는 애플리케이션은 모두 이런식으로 동작한다.

- 이벤트 타입: 이벤트 종류를 지정하는 문자열
ex: mousemove, keydown, load...

- 이벤트 대상: 이벤트가 일어난, 또는 이벤트와 연관된 객체
이벤트를 지정할 때는 'Window 객체의 load 이벤트'나 '<button> 요소의 click 이벤트' 처럼 반드시 그 타입과 대상을 지정해야한다.
클라이언트 사이드 js 애플리케이션에서 가장 널리 쓰이는 이벤트 대상은 Window, Document, Element 객체지만 일부 이벤트는 다른 객체에서 일어나기도 한다.

- 이벤트 핸들러 또는 이벤트 리스터
이 함수는 이벤트를 처리하거나 이벤트에 반응한다. 지정된 대상에서 지정된 타입의 이벤트가 일어나면 브라우저가 이벤트 핸들러를 호출한다. 객체에서 이벤트 핸들러가 호출되면 브라우저가 이벤트를 '일으켰다','전달했다'라고 한다.

- 이벤트 객체
이벤트 객체는 특정 이벤트와 연관되어 있으며 해당 ㅇ ㅣ벤트에 관한 세부 정보를 포함한다. 이벤트 객체는 이벤트 핸들러 함수에 인자로 전달된다.
모든 이벤트 객체에는 이벤트 타입을 나타내는 type프로퍼티, 이벤트 대상을 나타내는 target 프로퍼티가 있다.

- 이벤트 전달
브라우저는 이 프로세스를 통해 어떤 객체에서 이벤트 핸들러를 호출할지 결정한다.
Window객체의 load 이벤트나 Worker 객체의 message 이벤트처럼 특정 객체에 국한되는 이벤트는 전달이 필요없다.
반면 HTML 문서의 요소에서 일어나는 일부 이벤트는 문서 트리를 따라 전달된다.


15.2.1 이벤트 범주
- 장치 의존적인 입력 이벤트: mousedown, mouseup, touchstart, keydown 등
- 장치 독립적인 입력 이벤트: click(마우스 클릭 또는 키보드 ㅇ ㅣㅂ력, 터치 장치 등 됨)
input 이벤트는 keydown 이벤트의 장치 독립적인 대안이다.
- 사용자 인터페이스 이벤트: 텍스트 입력 필드가 키보드 포커스를 받았을  때 발생하는 focus, 사용자가 폼 요소의  값을 바꿨을 때 발생하는 change 등
- 상태 전환 이벤트: load, DOMContentLoaded 등
- API ㅈ ㅓㄴ용 이벤트: <video>요소의 waiting, playing 등, 

15.2.2 이벤트 핸들러 등록
기본적으로 두 가지다. 첫 번째 ㅂ ㅏㅇ법은 이벤트 대상인 요소나 객체에 프로퍼티를 설정한다.
두 번째 방법은 객체나 요소의 addEventListener() 메서드에 핸들러를 전달한다.

이벤트 핸들러 프로퍼티 설정
가장 단순한 방법이다. 이벤트 대상의 프로퍼티를 원하는 이벤트 핸들러 함수로 설정하는 방법이다. 프로퍼티 이름은 onclick, onchange, onload 처렁 on 다음에 이벤트 이름을 붙인다.
```
ex: 
window.onload = function() { 
  let form = document.  querySelector("form#shipping");
  form.onsubmit = 
  ...
}
```
**이벤트 핸들러 프로퍼티의 단점은 이벤트 대상이 이벤트 타입 하나당 최대 한 ㄱ ㅐ의 핸들러만 받는다는 가정 하에 설계됐다는 점이다.**
addEventListener()는 이전에 등록한 핸들러를 덮어쓰지 않으므로 일반적으로 addEventListener()가 더 낫다.

이벤트 핸들러 속성 설정
요소의 이벤트 핸들러 프로퍼티는 대응하는 HTML 태그의 속성으로 직접 정의할 수도 있다. 예를 들어 Window 요소에 등록할 핸들러를 HTML <body> 태그의 속성으로 정의할 수 있다. 최신 웹 개발에서는 거의  사용하지 안ㄶ지만 어쨌든 가능은 하다.

addEventListener()
Widnwo, Document, Element 객체는 모두 이벤트 대상이 될 수 있으며 이들의 addEventListener() 메서드를 통해 해당 객체에 이벤트 핸들러를 등록할 수 있다. addEventListener()는 인자 3개를 받는다.
첫 번째는 이벤트 타입이다. 이벤트 타입(이름)은 문자열이며 전치사 on은 사용하지 않는다.
두 번째 인자는 지정된 이벤트 ㅌ ㅏ입이 일어날 때 호출될 함수이다. 
세 번째 인자는 선택사항으로 받으며, 불 값  또는 객체이다. true를 전달하면 함수는 캡처링 이벤트 핸들러로 등록되며 이벤트 전달의  다른 단계에서 호출된다.

같은 객체에서 addEventListener 함수를 여러번 일어나면 ㅎ ㅐ당 타입의 ㅇ ㅣ벤트에 등록된 핸들러가 등록 순서대로 호출된다. (캡쳐링: 이벤트가 발생한 요소를 찾기 위해 브라우저가 해당 객체까지 탐색하는 것으로, 예시로 <button> 이벤트 발생 시 Window -> Document -> HTML -> body -> div -> button 과 같은 것이다. 반대는 버블링 이라고 한다)

이벤트 핸들러 인자
이벤트 핸들러는 인자로 이벤트 객체 하나만 받는다.
type: 일어난 이벤트 타입
target: 이벤트가 일어난 객체
currenntTarget: 전달되는 이벤트라면 현재 이벤트 핸들러가 ㄷ ㅡㅇ록된 객체
timeStamp
isTrusted: 웹 브라우저 자체에서 전달한 이벤트는 true, 자바스크립트 코드가 전달한 이벤트는 false
