## 15.1 웹 프로그래밍 기본

- 웹에서 자바스크립트 프로그램을 구성하는 방법
- 웹 브라우저로 불러오는 방법
- 자바스크립트 프로그램이 입력을 받고 출력하는 방법
- 이벤트에 반응해 비동기적으로 실행되는 방법

웹 브라우저는 HTML 문서를 표시한다. **웹 브라우저에서 자바스크립트 코드를 실행하려면
그 코드를 HTML 문서에 포함 또는 참조해야한다.** <script>태그는 그 역할을 한다.

<script>태그 안에 자바스크립트 코드를 직접 삽입할 수 있지만, src 속성을 써서 자바스크립트 코드를 포함한 파일의 URL을 지정하는게 일반적이다.
ex:
```
<scrlpt 5rc=''5cript5/digital-cIock.js''></5cript>
```
js파일에는 순수한 js만 있을 뿐 <script>태그나 기타 HTML은 포함되지 않는다.

페이지 렌더링 시 지연된 스크립트는 문서 출처 순서대로 실행된다. 비동기(async)스크립트는 불러오는 즉시 실행되므로 문서 출처대로 실행되지 않을 수 있다.

Document 객체는 브라우저 창이나 탭에 표시되는 HTML 문서를 나타내는 객체이며 클라이언트 사이드 자바스크립트 프로그래밍에서 가장 중요한 객체 중 하나이다.
HTML 문서를 다루는 API를 문서 객체 모델 또는 DOM이라 부른다. 

DOM API는 HTML 문서의 트리 구조를 반영한다. 문서에 존재하는 태그마다 자바스크립트 객ㅊ체가 있고, 문서에 존재하는 텍스트마다 그에 대응하는 텍스트 객체가 있다.

각 HTML 태그 타입에 대응하는 자바스크립트 클래스가 있고 문서에 존재하는 각 태그는 클래스의 인스턴스로 표현된다.
예를 들어  <body> 태그는 HTML BodyElement의 인스턴스이며, <table>태그는 HTML TableElement의 인스턴스이다.

브라우저 창이나 탭마다 이에 대응하는 전역 객체가 하나씩 있다. 워커 스레드를 제외한 모든 자바스크립트 코드는 ㅈ ㅓㄴ역 객체를 공유한다. 문서에 스크립트나 모듈이 얼마나 많든 관계없다. 스크립트에서 전역 객체에 프로퍼티를 정의하면 그 프로퍼티는 다른 스크립트 전체에서 볼 수 있다. 
자바스크립트의 표준 라이브러리는 전역 객체에 정의된다. 웹 브라우저에서 전역 객ㄱ체는 다양한 웹 API의 진입점이기도 하다. 예를들어 document프로퍼티는 현재 문서를 나타내고 fetch() 메서드는 HTTP 네트워크 요청을 보내며 Audio() 생성자는 자바스크립트 프로그램에서 사운드를 재생한다.

이 창에는 window 프로퍼티가 있으며 그 값은ㄴ 전역 객체 자체이다. 따라서 클라이언트 사이드 코드에서 window를 입력해 전역 객체를 참조할 수 있다.

어떤 스크립트에서 함수를 정의하고 다른 스크립트에서 클래스를 정의한다면 세 번째 스크립트에서는 그들을 가져오지 않고도 함수를 호출하고 클래스의 인스턴스를 만들  수 있다. 따라서 모듈을 사용하지 않는다면 문서에 존재해ㅏ는 독립적인 스크립트들이 네임스페이스를 공유하며 거대한 스크립트의 일부인 것처럼 행동한다. 작은 프로그램에서는 편리할 수도 있지만 큰 프로그램에서는 겹치는 이름을 피하는 일도 고역이 ㄷ ㅚㄹ 수 있으며 서드 파티 라이브러리를  사용한다면 이 문제가 더 커질 수 있다.

windows는 브라우저 창을 나타내는 전역 객체이고, window.documnent는 현재 HTML 문서를  나타내는 Document 객체이다.

자바스크립트 프로그램은 두 ㄷ ㅏㄴ계로 실행된다.
첫 번째 단계에서는 문서 콘텐ㅊ츠를 불러오고 <script>요소의 코드를 실행한다.
문서 로딩이 끝나고 스크립트를 전부 실행하면 두 번째 단계이다. 이  단계는 비동기적임며 이벤트 주도적이다. 두 번째 단계에서 동작하려면 반드시 첫 번째 단계에서 하나 이상의 이벤트 핸들러나 콜백 함수를 등록해야한다.
웹 브라우저는 비동기적으로 일어나는 이벤트에 응답해 이벤트 핸들러나 기타 콜백을 호출한다. 문서 로딩이 끝나면, 문서가 웹 브라우저에 표시되는 동안 이벤트 주도적인 두 번째 단계가 계속 이어진다.

js는 싱글 스레드 언어이며, 두 이벤트 핸들러가 절대 동시에 실행되지 않는다.싱글 스레드는 브라우저가 스크립트와 이벤트핸들러를 실행하는 동안 사용자 입력에 반응하지 않는다. 따라서 js프로그래머는 스크립트와 이벤트 핸들러가 너무 ㅇ ㅗ래실행되게 ㅎ ㅐ서는 안된다.
