#### 브로드캐스트 컨트롤
스위치가 패킷의 도착지 주소를 모르면 패킷을 플러딩한다. 전체 네트워크에 플러딩하는 것이 네트워크 성능에 무리가 갈 수 있다고 생각할 수 있지만
LAN은 크기가 작아 플러딩에 대한 영향이 작고 NIC은 도착한 패킷이 자신의 주소가 아니면 패킷을 버리기에 플러딩 작업은 네트워크에 큰 무리를 주지 않는다.

반면, 라우터는 패킷을 원격지로 보내는 것을 목표로 개발되어 분명한 도착지 정보가 있을 때만 통신을 허락한다.
인터넷 연결은 대부분 지정된 대역폭만 빌려 사용하므로 쓸모없는 통신이 네트워크를 차지하는 것을 최대한 막으려 노력한다.
라우터는 바로 연결되어 있는 네트워크 정보를 제외하고 경로 습득 설정을 하지 않으면 패킷을 포워딩 할 수 없다.
라우터의 기본 동작은 멀티캐스트 정보를 습득하지 않고 브로드캐스트 패킷을 전달하지 않는다. 이 기능을 '브로드캐스트 컨트롤 / 멀티캐스트 컨트롤'이라고 한다.
네트워크에 브로드캐스트가 많이 발생하는 경우, 라우터로 네트워크를 분리하면 브로드캐스트 네트워크를 분할해 네트워크 성능을 높일 수 있다.

#### 프로토콜 변환
라우터는 3계층 주소 정보를 확인하고 그 정보를 기반으로 동작한다. 라우터에 패킷이 들어오면 2계층까지의 헤더 정보를 벗겨내고 3계층 주소를 확인한 후 2계층 헤더 정보를 새로 만들어 외부로 내보낸다.
따라서 라우터에 들어올 때의 패킷 2계층 헤더 정보와 나갈 때의 패킷 2계층 헤더 정보가 다른 것이다. 이 기능을 이용하면 전혀 다른 기술 간 변환이 가능하다.
LAN 구간에서 패킷이 라우터를 지나면서 2계층까지의 헤더가 벗겨지고 WAN 구간으로 패킷이 나올 때 PPP헤더로 변경되어 프로토콜이 변환된다.

- LAN → 라우터
```
[Ethernet 헤더]
출발지 MAC : PC의 MAC
목적지 MAC : 라우터 LAN 인터페이스의 MAC

[IP 헤더]
출발지 IP : 192.168.0.10
목적지 IP : 8.8.8.8

[데이터]
```
- 라우터 내부
```
Ethernet Header 제거
→ IP 목적지 확인
→ 라우팅
```
- 라우터 -> WAN
WAN이 Ethernet이면:
```
새 Ethernet Header
출발지 MAC = 라우터
목적지 MAC = 다음 홉 라우터
```
WAN이 PPP라면:
```
PPP Header
→ MAC 주소 개념 없음
```

**Ethernet은 '유선 LAN 기술'만을 말하지 않는다.**
Ethernet의 정확한 의미는: 같은 2계층 링크에서 데이터를 어떤 형식의 프레임으로 만들어 전달할지 정한 기술 규약이다.
그리고 조금 이해하기 쉽게 풀어 설명하면, Ethernet은 MAC 주소를 사용하는 Ethernet Frame을 기반으로, 같은 L2 네트워크에서 데이터를 전달하는 기술.

이더넷의 핵심은 다음과 같다.
```
Ethernet Frame

┌──────────────────┐
│ Destination MAC  │
├──────────────────┤
│ Source MAC       │
├──────────────────┤
│ EtherType        │
├──────────────────┤
│ Data             │
│ (IP Packet)      │
├──────────────────┤
│ FCS              │
└──────────────────┘
```
즉 IP패킷을 이렇게 감싸서 보내는게 Ehternet의 L2 부분이다.
그리고 Ehternet 규격은 L2 뿐 아니라 L1의 전송 방식/매체 규격도 포함한다. 예를 들어 UTP 케이블 기반 Ethernet도 있고 광섬유 기반 Ethernet도 있다.

PPP는 Point-To-Point Protocol의 약자로, 두 장비가 1:1로 연결된 링크에서 데이터를 주고받기 위한 L2 프로토콜이다.
```
Ethernet
여러 장비가 존재할 수 있음

PC ─┐
PC ─┼─ Switch ─ Router
PC ─┘

→ 누구에게 보낼지 구분해야 함
→ MAC 주소 사용
```
```
PPP (Point-to-Point)

Router A ───────────── Router B
              ↑
        둘밖에 없음
```

결국 Ehternet과 PPP 둘 다 IP 패킷을 다음 구간으로 운반하기 위해 감싸주는 L2 기술이라는 공통점이 있다.
**Ethernet: L2에서 MAC 주소를 이용해 상대를 구분하며 프레임을 전달
PPP: 두 장비가 1:1로 연결된 링크에서 사용하는 L2 프로토콜이라 MAC 주소가 필요 없음**

#### 경로 지정 - 라우팅/스위칭
라우터가 패킷을 처리할 때는 크게 두 가지 작업을 수행한다.
- 경로 정보를 얻어 경로 정보를 정리하는 역할
- 정리된 경로 정보를 기반으로 패킷을 포워딩하는 역할

라우터는 자신이 모르는 주소의 목적지를 가진 패킷이 들어오면 버리므로, 패킷이 들어오기 전에 경로 정보를 충분히 수집하고 있어야한다.
클래스리스 네트워크로 전환된 후에는 같은 클래스의 주소조차 서브네팅된 상태로 분산되어 존재하므로 경로 정보가 기존보다 많아졌다.

**서브넷(Subnet) = 서브넷 마스크에 의해 구분된 하나의 IP 네트워크 영역**

라우터는 서브넷 단위로 라우팅 정보를 습득하고 라우팅 정보를 최적화하기 위해 서머리(Summary) 작업을 통해 여러 개의 서브넷 정보를 뭉쳐 전달한다.
그래서 라우터에 들어온 패킷의 목적지 주소와 라우터가 갖고 있는 라우팅 테이블 정보가 정확히 일치하지 않더라도 수많은 정보 중 목적지에 가장 근접한 정보를 찾아 패킷을 포워딩 해애ㅑ한다.

#### 라우팅 동작과 라우팅 테이블
인터넷에서는 단말부터 목적지까지의 경로를 모두 책임지는 것이 아니라 인접한 라우터까지만 경로를 지정하면 인접 라우터에서 최적의 경로를 다시 파악한 후 라우터로 패킷을 포워딩한다.
네트워크를 한 단계씩 뛰어넘는다는 의미로 이 기법을 홉-바이-홉(Hop-by-Hop) 라우팅이라고 부르고 인접한 라우터를 넥스트 홉 이라고 부른다.
라우터는 패킷이 목적지로 가는 전체 경로를 파악하지 않고 최적의 넥스트 홉을 선택해 보내준다.

넥스트 홉을 지정할 때는 세 가지 방법을 일반적으로 사용할 수 있다.
- 다음 라우터의 IP를 지정하는 방법(넥스트 홉 IP 주소)
- 라우터의 나가는 인터페이스를 지정하는 방법
- 라우터의 나가는 인터페이스와 다음 라우터의 IP를 동시에 지정하는 방법

| 정보                       | 질문                                           |
| ------------------------ | -------------------------------------------- |
| **라우팅 테이블의 Next Hop IP** | **다음에 어느 라우터로 갈 것인가?**                       |
| **Next Hop의 MAC 주소**     | **그 라우터에게 이 Ethernet 프레임을 실제로 어떻게 전달할 것인가?** |

라우터에서 넥스트 홉을 지정할 때는 일반적으로 상대방 라우터의 인터페이스 IP 주소를 지정하는 방법을 사용한다.
`인터페이스 = 라우터가 네트워크와 연결되는 출입구`라고 생각하면 된다.

```
① Next Hop IP 지정

2.2.2.0/24 → 10.0.0.2로 보내라
                   ↑
             상대 Router B


② 인터페이스 지정

2.2.2.0/24 → eth1으로 내보내라
                   ↑
             내 Router A의 포트
```
라우터가 패킷을 포워딩할 경로를 선택할 때는 출발지를 고려하지 않는다. 따라서 라우팅 테이블을 만들 때는 목적지 정보만 수집하고 목적지 주소를 확인해 패킷을 넥스트 홉으로 포워딩한다.
라우팅 테이블에 저장하는 정보는 다음과 같다.
- 최종 목적지 주소
- 넥스트 홉 IP 주소. 나가는 로컬 인터페이스(선택 가능)
